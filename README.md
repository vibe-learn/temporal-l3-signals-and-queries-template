        # temporal — Сигналы и запросы

        Homework-шаблон для урока **l3_signals_and_queries** (Сигналы и запросы) на платформе Vibe Learn.

        ## Что делать

        На go.temporal.io/sdk реализуй OrderWorkflow с состоянием items. Добавь: сигнал "add-item"
(workflow.GetSignalChannel + Selector, мутирует items), query "current-items"
(workflow.SetQueryHandler, read-only возвращает items и сумму), и Update "add-item-checked"
(workflow.SetUpdateHandlerWithOptions с валидатором, который отклоняет товар не на складе,
а хендлер мутирует и возвращает новую сумму). Тесты на TestWorkflowEnvironment: SignalWorkflow
добавляет товар; QueryWorkflow возвращает текущее состояние и НЕ меняет его; Update с невалидным
товаром отклоняется валидатором и не пишется в историю, с валидным — мутирует и возвращает сумму.

## Контекст (из transfer-задачи урока)

Ты делаешь workflow OrderWorkflow, который живёт, пока заказ собирается. Требования от продукта:
(1) пользователь может в любой момент добавить товар в заказ из мобильного приложения;
(2) приложение должно показывать текущий список товаров и сумму, опрашивая заказ;
(3) при добавлении товара нужно тут же отказать, если товара нет на складе, и вернуть
    приложению актуальную сумму заказа; (4) первый «добавить товар» может прийти раньше,
    чем заказ-workflow вообще создан.

**Вопрос:** какой примитив взаимодействия (Signal / Query / Update / SignalWithStart) ты
возьмёшь для каждого требования и почему? Особо обоснуй (2) vs (3).

## Recap из урока

- **Signal** — асинхронный вход В workflow: пишется в историю, МОЖЕТ мутировать состояние, отправителю результат не возвращает (принимается через GetSignalChannel).
- **Query** — синхронное read-only чтение состояния: НЕ мутирует, НЕ пишется в историю, обработчик обязан быть side-effect-free и детерминированным (может выполниться при replay).
- Никогда не мутируй состояние и не делай I/O в query-хендлере — это недетерминизм.
- **Update** — третий примитив: синхронно мутирует И возвращает результат, плюс валидатор отклоняет апдейт ДО записи в историю. Нужны мутация+ответ → бери Update, а не «signal+query».
- **SignalWithStart** — атомарно: сигнал существующему workflow или старт+сигнал нового, без гонки «проверить-и-создать».

        ## Как работать

        1. Платформа Vibe Learn создаёт копию этого репо в твоём GitHub-аккаунте по клику «Начать домашку» на странице урока (через GitHub `/generate`, codecrafters-pattern).
        2. Склонируй копию локально, реализуй TODO в `main.go` (workflow + активности), прогони тесты, запушь.
        3. CI (`.github/workflows/ci.yml`) запускает `go vet` + `go test ./...` на каждый push. Платформа слушает результат через webhook от GitHub Actions и обновляет статус домашки на странице урока.

        ## Локальное окружение

        - Go 1.22+
        - SDK: `go.temporal.io/sdk`
        - Docker + docker-compose — `docker compose up` поднимает Temporal dev server на `:7233` + Web UI на `:8233`. Адрес переопределяется через env `TEMPORAL_ADDRESS` (дефолт `localhost:7233`).
        - Юнит-тесты на `testsuite.TestWorkflowEnvironment` (активности замоканы) бегут в CI БЕЗ сервера; интеграционный тест включается через `TEMPORAL_INTEGRATION=1`.

        ## Запуск

        ```bash
        # Поднять локальный Temporal dev server + UI
        docker compose up -d
        # Web UI: http://localhost:8233

        # Прогнать тесты (юнит на TestWorkflowEnvironment — без сервера;
        # интеграционный включается через TEMPORAL_INTEGRATION=1)
        go test ./...
        TEMPORAL_INTEGRATION=1 go test ./...

        # Запустить воркер (регистрирует workflow + активности, слушает task queue)
        go run .
        ```
